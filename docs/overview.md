# Brothereye — System Overview

## What it does

Brothereye monitors factory workers via IP / USB cameras, recognises what action
each worker is performing in real time, counts production cycles, and tracks
whether a defined workflow sequence is being followed.

## How the AI pipeline works

Each camera frame goes through three detection layers in sequence.
The highest-confidence result wins.

```
Camera frame
    │
    ├─ YOLO Pose          → finds people, skeleton keypoints
    ├─ YOLO Segmentation  → finds person masks for privacy blur
    │
    └─ Per-person:
        │
        ├─ Layer 1  Tool Classifier (YOLOv8-cls)
        │           Crops the hand region and asks:
        │           "what tool is in this worker's hand?"
        │           screwdriver → screwing
        │           measuring tape → measure
        │           cutter → cutting
        │           component → place_part
        │           Requires training first (see training.md)
        │
        ├─ Layer 2  Wrist-Motion Heuristic  (instant, no training needed)
        │           Tracks the dominant wrist over 32 frames.
        │           Oscillating + localised motion → screwing
        │           High speed → moving
        │           Near-zero speed → idle
        │
        └─ Layer 3  X3D Video Classifier  (every 8 frames)
                    16-frame clip of the person crop fed to X3D-XS.
                    Requires training first (see training.md)
```

**Fusion rule:** Tool classifier wins when confidence ≥ TOOL_CONF_MIN.
Otherwise the wrist heuristic result is fused with the X3D result
(X3D weighted at 60 %).

## Cycle and workflow tracking

**Action cycles** — each time a worker sustains an action for ≥ 3 seconds
without interruption that counts as one completed cycle for that action.
Screwing additionally tracks wrist oscillation cycles (each full rotation).

**Workflow cycles** — an ordered sequence of steps (e.g. cutting → screwing →
place_part) is tracked per camera.  When every step is completed in order
the system fires a `workflow_complete` event and increments the cycle counter.

The workflow steps can be:
- Set manually via the API (`POST /api/workflow/<id>/setup`)
- Learned automatically from a reference video (`POST /api/workflow/<id>/learn`)

Workflow definitions are saved to `AI/runs/workflows/<camera_id>.json` and
reloaded automatically when the server restarts.

## Starting the server

```powershell
# Pull updates and start
.\start.ps1

# Or start directly
.venv\Scripts\python.exe AI\server.py

# Auto-start cameras on boot
$env:INIT_CAMERAS = "cam1:0,cam2:rtsp://admin:pass@192.168.0.101:554/stream"
.venv\Scripts\python.exe AI\server.py
```

The dashboard is at `http://localhost:5000`

## Environment variables

| Variable | Default | Description |
|---|---|---|
| `PORT` | `5000` | HTTP server port |
| `HOST` | `0.0.0.0` | Bind address |
| `PG_DSN` | postgres://… | Postgres connection string |
| `ENABLE_X3D` | `1` | Load X3D model (`0` to disable) |
| `TOOL_CONF_MIN` | `0.60` | Min confidence to trust tool classifier |
| `POSE_CONF` | `0.35` | YOLO pose detection threshold |
| `JPEG_QUALITY` | `75` | Stream JPEG quality (1–100) |
| `STREAM_FPS` | `30` | Maximum stream frame rate |
| `INIT_CAMERAS` | `` | Comma-separated `id:source` pairs to start automatically |
| `N8N_ENABLED` | `0` | Enable n8n webhook forwarding |
| `CORS_ORIGINS` | `*` | Allowed CORS origins |
